# Feature: Baustellen-Verwaltung & Kalkulation (Admin-Only)

## Kontext
Im internen **NEOSOLAR-CRM** soll unter dem Menüpunkt **Kalkulation** ein neuer Admin-Bereich 
entstehen, der unsere bisherigen Excel-/Google-Sheet-Workflows für Baustellen-Tracking und 
Projekt-Kalkulation vollständig ablöst.

Hintergrund: Aktuell pflegen wir zwei parallele Sheets manuell – eine operative Baustellen-
Übersicht (Status der Bewilligungen, DC-/AC-Montage, offene Punkte) und eine 
Kalkulations-Übersicht (Material, Elektriker, Montage, VK, Marge, Tranchen A1/A2/A3). 
Das soll künftig direkt im CRM laufen, damit jede verkaufte Baustelle automatisch dort 
landet und sauber bis zur Schlussrechnung abgehakt werden kann.

## Struktur

Menüpunkt **Kalkulation** (admin-only) enthält zwei Subtabs:

1. **Baustellen** – operative Übersicht mit Status-Tracking (siehe Image 2)
2. **Kalkulation** – finanzielle Übersicht pro Baustelle (siehe Image 1)

Beide Subtabs greifen auf dieselbe Datenbasis zu. Eine Baustelle entsteht automatisch, 
sobald ein Lead/Kunde im CRM den Status "Verkauft" / "Vertrag unterschrieben" erreicht 
(Trigger oder Server Action).

## Zugriffsrechte

- Sichtbar ausschliesslich für Rolle `admin`
- Closer (z.B. Eileen) und andere Rollen sehen weder den Menüpunkt noch die Routen
- Durchsetzung doppelt: DB-seitig (RLS oder Equivalent) + UI-Guard
- Direkter URL-Aufruf durch Nicht-Admins → 403/404

## Datenmodell

### Tabelle `baustellen`
- `id` (uuid, pk)
- `kunde_id` (fk → kunden, unique) – Verknüpfung mit dem Kundendatensatz im CRM
- `closer_id` (fk → users) – Owner-Zuordnung (wer hat geclosed → relevant für Provision laut §4 Closer-Vertrag)
- `kunde_name`, `kunde_adresse`, `kunde_telefon`, `kunde_email` (denormalisiert für schnelle Tabellen-Anzeige)
- `im_crm` (boolean, default true)
- `bemerkung` (text)
- `fehlt_etwas` (text, nullable) – freier Text wie "Batterie fehlt", "Dongle fehlt", "Schaltschrank fehlt"
- `status` (enum: `offen`, `in_arbeit`, `kassiert`, `fakturiert`, `verlust`)
- `created_at`, `updated_at`

### Tabelle `baustellen_workflow` (1:1)
Pro Schritt jeweils Boolean + Datum:
- `baubewilligung` + `baubewilligung_am`
- `tag_eingereicht` + `tag_eingereicht_am`
- `tag_bewilligt` + `tag_bewilligt_am`  *(Sonderfall: Anmerkungen wie "8KW Rück" als optionales Notizfeld pro Schritt)*
- `ia_eingereicht` + `ia_eingereicht_am`
- `ia_bewilligt` + `ia_bewilligt_am`
- `dc_montage_termin` (date)
- `dc_montage_ausgefuehrt` + `dc_montage_ausgefuehrt_am`
- `ac_termin` (date)
- `ac_installiert` + `ac_installiert_am`

### Tabelle `baustellen_kalkulation` (1:1)
Kosten:
- `material_kranich` (numeric, CHF)

- **Lazy-Loading der Tabellen-Zeilen** (Virtual Scrolling). Aktuell rendert die Lead-Liste 50–500 Zeilen auf einmal. Bei langen Listen virtuelles Scrollen → fühlbar flüssiger.
- **Bundle-Splitting verbessern**: dein `index-*.js` ist 336 KB groß. Vendor-Libraries in eigenen Chunk → erste Page-Loads schneller.

**3. Größerer Umbau (für später)**
- **Server-side Pagination + Search** überall (statt erst alles laden, dann filtern)
- **Edge-Caching** (CDN für statische Assets ist OK, API-Responses könnten via Netlify Edge Cache gepuffert werden)
